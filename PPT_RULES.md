# 5. CONTENT WRITING

Do NOT paste long project documentation onto slides.

Convert information into concise presentation language.

BAD:

"TRACE-X utilizes an advanced spatio-temporal predictive analytics framework to analyze historical cybercrime complaints and financial transaction patterns in order to forecast potential cash withdrawal locations."

GOOD:

# PREDICT THE CASH-OUT

**WHERE?** Likely withdrawal zone

**WHEN?** Next 45 minutes

**WHY?** Transaction + behaviour + geography

**WHAT NEXT?** Optimal intervention

Prefer:

- Strong headlines
- Short supporting text
- Numbers
- Labels
- Callouts
- Visual explanations
- Short technical descriptions

Avoid:

- Paragraph-heavy slides
- Repetitive text
- Generic buzzwords
- Unnecessary jargon
- Overexplaining obvious concepts

---

# 6. ONE IDEA PER SLIDE

Every slide needs one dominant message.

A viewer should understand what the slide is saying within approximately three seconds.

Use this hierarchy:

**HEADLINE**
→ main idea

**SUPPORT**
→ one concise explanation

**VISUAL**
→ proof / mechanism / example

Do not put five different messages on one slide.

# 16. TEMPLATE PRIORITY RULE

If content conflicts with the template:

**PRESERVE THE TEMPLATE.**

If content does not fit:

1. Shorten the content.
2. Convert text into a visual.
3. Use another existing template layout.
4. Split the content into another slide if necessary.

DO NOT shrink the font until it becomes unreadable.

DO NOT redesign the slide to fit too much content.

---

# 17. VISUAL QA IS MANDATORY

After generating the PPTX:

1. Render every slide to images or PDF.
2. Inspect every slide.
3. Check for text overflow.
4. Check image cropping.
5. Check alignment.
6. Check typography.
7. Check readability.
8. Check spacing.
9. Compare against the original template.
10. Fix all problems.
11. Render again.
12. Perform another complete visual inspection.

Do not consider the presentation finished until all slides have passed visual QA.
